Test Scenario Menyeluruh

Daftar skenario uji gs.POS dari instalasi sampai alur bisnis end-to-end. Disusun dari docs/SPEC.md, docs/api/*, ADR 0001–0016, daftar route, dan app/Actions/*. Dokumen yang sama dibaca automation lewat JSON di dalam halaman ini.

Pendahuluan

Cara membaca & aturan eksekusi

Kolom skenario

ID{KATEGORI}-{NNN}, tetap dan tidak dinomori ulang. Dipakai automation sebagai nama test, mis. it('[ORD-012] …'). Skenario baru ditambah di akhir kategori.
PrioritasP1 kritis: uang, isolasi tenant, auth, kehilangan data · P2 fungsi utama · P3 tampilan/kenyamanan
TipePOS positif · NEG negatif/validasi · PERM permission · ISO isolasi tenant/outlet · IDEM idempotensi · CONC konkurensi · SEC keamanan · EDGE nilai batas · CALC perhitungan · E2E alur lintas modul
LayerUNIT Pest unit · ACT Action tanpa HTTP · API HTTP /api/v1 · WEB HTTP/Livewire/Filament · BRW browser Dusk · CMD artisan/scheduler · MYSQL wajib grup mysql
RefEndpoint, error.code, keputusan SPEC (Q…), atau ADR. Dipakai matriks keterlacakan di bagian akhir.

Persona & data uji

MGR-A SPV-A KSR-AManager, supervisor, kasir tenant A di outlet A1; supervisor & kasir punya PIN 6 digit + username
KSR-A2Kasir tenant A yang hanya ditugaskan ke outlet A2
OWN-B KSR-BTenant B sebagai pembanding isolasi
DEV-A1 DEV-A2Perangkat terdaftar di outlet A1 / A2
ADMSuper admin (guard terpisah; 2FA dimatikan via env uji kecuali skenario 2FA)
MEM-A GUESTMember tenant A · tamu self-order
Outlet A1Pajak 11% exclusive, service 5%, pembulatan Rp100, batas diskon kasir 10% / supervisor 25%, Asia/Jakarta

Aturan eksekusi

  • Data dibuat dengan factory / posSetup(), bukan seeder.
  • Jangan migrate:fresh/db:wipe atau menyentuh database/database.sqlite. Browser test memakai database/dusk.sqlite lewat ./vendor/bin/pest tests/Browser, bukan php artisan dusk.
  • Midtrans, email, dan storage backup selalu di-fake. Tidak ada request ke internet.
  • Waktu dibekukan (freezeTime/travelTo) untuk skenario tanggal, trial, kedaluwarsa, nomor order.
  • Setiap respons API dicek envelope-nya: success, message berbahasa Indonesia, data/error.code, meta.request_id.
  • Uang dibandingkan sebagai string desimal ("62000.00"); tanggal ISO 8601 UTC.
Tidak ada skenario yang cocok dengan filter.
