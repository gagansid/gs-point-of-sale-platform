# Laporan Audit Keamanan gs.POS — 2026-10-23

- **Auditor:** Claude (Opus 5.5) — white-box statis: pencarian sink eksekusi kode/webshell, upload, raw SQL, akses
  file, installer, paket rilis, otorisasi & isolasi tenant, webhook, logika voucher
- **Commit audit:** `cf9a946` (branch `feature/pos`); perbaikan `69d3c55`..`25b21a1`
- **Lingkungan:** lokal (PHP 8.2.26, Laravel 12.69.3, Livewire 4.4.7, Filament 5.10.1). Pest memakai SQLite `:memory:`;
  test `.env`/installer memakai folder sementara (DB & `.env` lokal tidak disentuh)
- **Pemicu:** permintaan pemilik untuk memeriksa celah "PHP → shell" (eksekusi kode jarak jauh) yang sedang ramai.
  Advisory spesifik dengan nama itu tidak bisa diverifikasi saat audit, jadi seluruh jalur umum menuju eksekusi
  kode/webshell di aplikasi PHP/Laravel diperiksa.

Tidak ditemukan sink eksekusi kode di kode aplikasi: tidak ada `eval`/`exec`/`system`/`unserialize`/`include`
dinamis dari input. Semua upload dibatasi MIME gambar/PDF/CSV/XLSX dengan nama file di-hash (tanpa SVG, tanpa nama
asli), raw SQL memakai binding, dan dependency bersih (`composer audit`, `npm audit`). Risiko terbesar justru di luar
kode, yaitu `APP_KEY` lokal yang ikut paket hosting. Pemegang key itu bisa memalsukan payload terenkripsi/bertanda
tangan, yang di ekosistem Laravel/Livewire merupakan jalur yang sudah terbukti menuju eksekusi kode. Tiga temuan
lain menyangkut pengambilalihan installer dan penyalahgunaan voucher.

## 4. Detail Temuan

### GSPOS-SEC-025 — `APP_KEY` lokal & password DB ikut paket hosting

| Field | Isi |
|---|---|
| Severity | High |
| Kategori | Secrets management (CWE-798 / CWE-321) |
| Status verifikasi | CONFIRMED |
| Lokasi | `dist/hosting/gspos-project.zip` → `gs-point-of-sale-platform/.env` (artefak lokal, `/dist` di-gitignore) |

**Deskripsi & root cause.** Paket hosting manual dibuat dengan menyalin `.env` produksi ke dalam zip. `APP_KEY` di
dalamnya identik dengan `.env` lokal (dibandingkan lewat hash), dan zip juga memuat `DB_PASSWORD`. Dump
`gspos-database.sql` memuat 31 hash bcrypt (pengguna + 1 admin) dan secret Turnstile terenkripsi dengan key yang sama.

**Dampak.** Siapa pun yang memegang zip, laptop developer, atau salinan `.env` lokal bisa mendekripsi data rahasia
(key Midtrans, secret 2FA admin) serta memalsukan cookie terenkripsi, session, signed URL, dan checksum snapshot
Livewire. Riset publik berulang kali menunjukkan `APP_KEY` yang bocor di Laravel/Livewire bisa dinaikkan menjadi
eksekusi kode jarak jauh.

**Perbaikan.**
- `App\Actions\Admin\RotateAppKey` + `php artisan pos:rotate-key [--keep-previous] [--force]`, dengan urutan aman
  bila terhenti:
  1. `.env` diisi key baru, key lama sementara di `APP_PREVIOUS_KEYS`;
  2. enkripsi ulang `payment_gateway_settings.server_key/client_key`, `admins.app_authentication_secret/_recovery_codes`,
     dan `SystemSettings::encryptedKeys()` dalam satu transaksi;
  3. hapus session web;
  4. kosongkan `APP_PREVIOUS_KEYS`.

  Nilai yang sudah tidak terbaca dilaporkan, tidak dihapus.
- `scripts/release/check-package.sh <zip>` menolak `.env`, database/dump, log, status/kode installer, file session, dan
  kunci privat. Pemeriksaan ini dijalankan otomatis di akhir `build-package.sh`; pada paket `dist/hosting` saat ini
  hasilnya **DITOLAK** karena `.env`.
- Dokumen: `security.md` §4, `deploy.md`, `install.md`, README.

**Tindakan pemilik.** Bangun ulang `dist/hosting` tanpa `.env` di dalam zip. Unggah `.env` terpisah lewat File Manager,
lalu jalankan `pos:rotate-key` sekali di server. Simpan `.env` produksi di password manager. Hapus salinan zip lama yang
pernah dibagikan.

**Test regresi.** `tests/Feature/Security/GspoSec025AppKeyRotationTest.php` (5 test): data tetap terbaca dengan key
baru dan tidak lagi dengan key lama, session dihapus, `--keep-previous`, aman diulang, nilai tak terbaca, konfirmasi
command, `.env` tidak ada.

### GSPOS-SEC-026 — Installer bisa diambil alih bila `INSTALL_TOKEN` kosong

| Field | Isi |
|---|---|
| Severity | Medium |
| Kategori | Broken access control (CWE-306) |
| Status verifikasi | CONFIRMED |
| Lokasi | `app/Support/Installer/Installation.php` (`tokenMatches`: token null → lolos), `config/pos.php` |

**Deskripsi & root cause.** Kode instal bersifat opsional. Tanpa `INSTALL_TOKEN`, siapa pun yang membuka domain sebelum
pemilik bisa menjalankan seluruh installer. Selama instal berlangsung, status langkah berlaku global sementara data
form diambil dari session pemanggil.

**Dampak.** Penyerang bisa menginstal aplikasi dengan database dan super admin miliknya (menguasai server pelanggan),
atau memakai **Tes koneksi** database untuk memindai host/port internal (10/menit).

**Perbaikan.** Kode instal kini selalu wajib. Bila `INSTALL_TOKEN` kosong, installer membuat kode acak 12 karakter
(±60 bit, alfabet tanpa karakter mirip) di `storage/app/install-code.txt` dengan izin 0600, yang hanya bisa dibaca
lewat akses server. Installer gagal tertutup bila tidak ada kode yang berlaku. ID session diganti setelah kode benar,
dan file kode dihapus saat instal selesai. Pengikatan status ke satu session tidak diperlukan, karena semua langkah
kini menuntut bukti akses server.

**Test regresi.** `WebInstallerTest` › *GSPOS-SEC-026: tanpa INSTALL_TOKEN installer tetap terkunci kode acak…*,
*INSTALL_TOKEN diisi…*, *gagal tertutup*.

### GSPOS-SEC-027 — Kode voucher bisa ditebak lewat pesan dari meja

| Field | Isi |
|---|---|
| Severity | Medium |
| Kategori | Brute force / user enumeration (CWE-307, CWE-204) |
| Status verifikasi | CONFIRMED |
| Lokasi | `app/Livewire/SelfOrder/OrderPage.php` (`quote()`, `voucherCode`), `app/Livewire/Cashier/PointOfSale.php` (`applyVoucher`, `appliedVoucherCode`) |

**Deskripsi & root cause.** Endpoint API `/vouchers/check` sudah dibatasi 30/menit, tetapi halaman publik pesan dari
meja mengecek `voucherCode` di setiap render Livewire tanpa batas. Pesan gagalnya juga membedakan *tidak ditemukan*
dari *kedaluwarsa* / *khusus member* / *minimal belanja*. Di kasir web, `appliedVoucherCode` bisa diisi langsung dari
client sehingga `applyVoucher()` terlewati.

**Dampak.** Siapa pun yang memegang URL QR meja bisa menebak kode promo pendek buatan owner tanpa batas dan tahu kode
mana yang ada.

**Perbaikan.** `App\Support\VoucherAttempts`:
- Pesan dari meja: setiap kode **baru** dihitung sebelum dicek ke database, dengan batas 10/menit per IP dan 30/menit
  per meja. Hanya kode yang lolos (`#[Locked] checkedVoucher`) yang dihitung dan dikirim. Semua alasan
  `VOUCHER_INVALID` dijawab dengan satu pesan seragam.
- Kasir web: batas 30/menit per user, dan `appliedVoucherCode` diberi `#[Locked]`.

**Test regresi.** `tests/Feature/Security/GspoSec027VoucherGuessingTest.php` (5 test).

### GSPOS-SEC-028 — Voucher ulang tahun bisa didapat berulang

| Field | Isi |
|---|---|
| Severity | Medium |
| Kategori | Business logic abuse (CWE-840) |
| Status verifikasi | CONFIRMED |
| Lokasi | `app/Http/Controllers/Web/Member/PortalController.php` (`updateProfile`), `app/Actions/Member/IssueBirthdayVouchers.php` |

**Deskripsi & root cause.** Member bebas mengganti tanggal lahir di halaman member, sementara anti-dobel voucher hanya
per awal bulan (`starts_at`). Pendaftaran member tidak memakai OTP (batasnya 5 akun/jam/IP).

**Dampak.** Pertama, member bisa memindah bulan lahir ke bulan berjalan setiap bulan dan mendapat voucher 12×/tahun.
Kedua, akun palsu baru dengan bulan lahir = bulan ini langsung mendapat voucher pribadi yang bisa dipakai saat
pesan dari meja.

**Perbaikan.**
- `UpdateOwnMemberProfile`: tanggal lahir hanya bisa diisi sekali di halaman member. Setelah terisi, perubahan
  ditolak dengan pesan jelas dan hanya kasir/owner yang bisa mengubahnya.
- `IssueBirthdayVouchers`: maksimal satu voucher per member per tahun kalender (WIB), dan hanya untuk member yang
  `created_at` < awal bulan lahirnya.

**Test regresi.** `tests/Feature/Security/GspoSec028BirthdayVoucherAbuseTest.php` (4 test, termasuk isolasi tenant).

### GSPOS-SEC-029 — Versi PHP

| Field | Isi |
|---|---|
| Severity | Low |
| Kategori | Komponen usang (CWE-1104) |
| Status verifikasi | CONFIRMED di lokal; server produksi belum ada |
| Lokasi | runtime |

PHP lokal 8.2.26 (Nov 2024) sudah tertinggal beberapa rilis patch, dan dukungan keamanan PHP 8.2 berakhir 31 Des 2026.
**Rekomendasi:**
- Di cPanel (MultiPHP Manager) pilih patch 8.2.x terbaru, jalankan lewat PHP-FPM/LSAPI (bukan CGI), dengan
  `expose_php=Off` dan `display_errors=Off`.
- Rencanakan uji suite di PHP 8.3/8.4 sebelum 2027. ADR 0004 membatasi fitur bahasa, bukan versi runtime.

## 5. Yang diperiksa & aman

- **Sink eksekusi kode:** tidak ada `eval`, `exec`/`shell_exec`/`system`/`passthru`/`proc_open`/`popen`, `unserialize`,
  `extract`, atau `include`/`require` dinamis dari input (`proc_open` hanya dicek sebagai syarat backup).
- **Upload:** semua `FileUpload` memakai `acceptedFileTypes` (jpeg/png/webp, PDF untuk bukti bayar, CSV/XLSX di disk
  privat untuk import) dan batas ukuran. Nama file di-hash dengan ekstensi dari MIME, tanpa `preserveFilenames` dan
  tanpa SVG.
- **Penulis `.env` installer:** nama variabel divalidasi; baris baru, `$`, dan backtick ditolak; ditulis atomik 0640.
- **SQL:** semua `*Raw` memakai binding; interpolasi hanya untuk fragmen buatan server.
- **File:** unduh backup & pembaca log memakai path buatan server.
- **Webhook Midtrans & billing:** `hash_equals`, status dicek ulang ke API, nominal dicocokkan, replay ditolak.
- **Isolasi tenant, permission, PIN, rate limit login, 2FA admin, expiry token Sanctum, XSS:** sesuai audit
  2026-10-10, tanpa regresi.
- **Header & `.htaccess`:** dotfile/`.sql`/`.log` diblokir, HTTPS dipaksa, HSTS, `X-Frame-Options: DENY`, CSP API.
- **Dependency:** `composer audit` & `npm audit --omit=dev` bersih.
